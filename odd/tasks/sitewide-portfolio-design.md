### Implementation assumptions and boundaries

- Site copy stays in English, matching the existing project. Preserve factual content, policy text, contacts, social URLs, SEO metadata, the published Meta verification tag and dependencies.
- This scope covers UI routes, not changes to pages/api/hello.js or authentication/business behavior.
- Shared foundation: components/PageShell.js exports a default component with eyebrow, title, description and children props. It renders one h1 with id page-heading and a section.site-page. Use it on every non-home UI route. SEOHead stays at the page level.
- Shared CSS classes: site-page, site-eyebrow, site-title, site-description, site-surface, site-prose, site-button, site-button-secondary, site-input and site-footer. Palette: background #0b0d14, surface #12151e, white/10 borders, slate text, violet-300 accent. Shared container matches Home: max-w-7xl, px-6/sm:px-8, xl:pr-40, pt-56/sm:pt-44/lg:pt-48.
- Remove old route-specific fixed gradient backgrounds, Circles/Bulb/FloatingCard decoration and large entry animations from the pages being unified. Keep interactive state and data. Do not hide overflow to conceal broken layouts; remove the old off-canvas decoration from the redesigned routes.
- The user-owned dev server stays on port 3000. Do not stop it, install dependencies, or run a production build into its .next. Parent owns isolated build and whole-site Chrome checks.
- All UI work remains local and uncommitted until the user chooses delivery. Only the earlier Meta-tag commit a38df7a is published. Existing uncommitted first-stage files are part of the approved visual baseline and must not be overwritten indiscriminately.
- Forecast: roughly 1,200-1,800 authored changed lines across independent page families; no generated changes. Delivery strategy remains ask-on-risk if/when commits or PRs are authorized. Do not minify, omit checks or split artificially to meet a line heuristic.
